# 라이딩 기록 — 시작 / 종료 / 거리 누적

> MapPage 왼쪽 패널의 **"라이딩 시작"** 버튼 기능. 커밋 `fc694e6` 로 프론트가 먼저 구현됐고,
> 저장을 받아줄 백엔드(`RideRecordController`)는 나중에 추가됐다.

## 화면 동작

```
[라이딩 시작]  ← 초록 버튼
     ↓ 누르면
[라이딩 종료]  ← 빨간 버튼으로 바뀌고 아래에 실시간 표시
   시간: 12:34
   거리: 4.21km
     ↓ 누르면
   POST /api/ride-records → "주행 기록 저장됨! 4.21km · 34분" 토스트
```

## 1. Haversine — 두 GPS 좌표 사이 거리 구하기

지구는 평면이 아니라서 위경도 차이를 피타고라스로 계산하면 틀린다.
**Haversine 공식**은 구(球) 위의 두 점 사이 최단거리(대권거리)를 구한다.

```js
const calculateDistance = (lat1, lng1, lat2, lng2) => {
  const R = 6371000;                                  // 지구 반지름 (미터)
  const dLat = (lat2 - lat1) * Math.PI / 180;         // 도(degree) → 라디안
  const dLng = (lng2 - lng1) * Math.PI / 180;
  const a = Math.sin(dLat / 2) ** 2 +
            Math.cos(lat1 * Math.PI / 180) * Math.cos(lat2 * Math.PI / 180) *
            Math.sin(dLng / 2) ** 2;
  return R * 2 * Math.asin(Math.sqrt(a));             // 미터
};
```

- `R` 을 6371000(미터)로 두면 결과가 미터로, 6371로 두면 km로 나온다
- 삼각함수는 **라디안**을 받으므로 `× π / 180` 변환이 필수
- 몇 km 수준에서는 오차가 사실상 없다 (지구를 완전한 구로 가정하는 데서 오는 0.5% 이내 오차)

> 참고: 지오펜싱 쪽은 같은 계산을 Leaflet의 `map.distance()` 로 처리한다
> ([10_실시간_위치공유_지오펜싱.md](10_실시간_위치공유_지오펜싱.md)).
> 즉 **같은 계산이 프로젝트 안에 두 가지 방식으로 존재**한다.
> 라이딩 쪽은 지도 객체 없이도 돌아가야 해서 직접 구현했다.

## 2. 시작 — 타이머 + GPS 감시

```js
const handleRideStart = useCallback(() => {
  setIsRiding(true);
  setRideTime(0);
  setRideDistance(0);
  rideStartTimeRef.current = Date.now();

  if (!navigator.geolocation) return;

  // ① GPS 감시 — 움직인 만큼 거리를 더한다
  rideWatchIdRef.current = navigator.geolocation.watchPosition((pos) => {
    const { latitude, longitude } = pos.coords;

    if (!rideStartPosRef.current) {
      rideStartPosRef.current = { lat: latitude, lng: longitude };   // 첫 지점 기록
    } else {
      const dist = calculateDistance(
        rideStartPosRef.current.lat, rideStartPosRef.current.lng,
        latitude, longitude
      );
      if (dist > 5) {                                   // ★ 5m 이상 움직였을 때만 인정
        setRideDistance(prev => prev + dist);
        rideStartPosRef.current = { lat: latitude, lng: longitude };  // 기준점 갱신
      }
    }
  });

  // ② 1초 타이머 — 경과 시간
  rideTimerRef.current = setInterval(() => setRideTime(prev => prev + 1), 1000);
}, []);
```

**`dist > 5` 필터가 왜 필요한가**
GPS는 가만히 서 있어도 좌표가 몇 m씩 흔들린다(드리프트). 필터가 없으면 신호등에 서 있는
동안에도 거리가 계속 늘어난다. 5m 미만의 변화는 "안 움직인 것"으로 보고 무시한다.

**변수 이름 주의**: `rideStartPosRef` 는 이름과 달리 "출발 지점"이 아니라
**"마지막으로 거리를 잰 지점"** 이다. 누적 계산을 위해 계속 갱신된다.
(`rideLastPosRef` 가 더 정확한 이름 — 개선 후보)

**`setRideDistance(prev => prev + dist)` 형태를 쓰는 이유**
콜백 안에서 `rideDistance + dist` 라고 쓰면 콜백이 만들어질 당시의 낡은 값을 쓰게 된다.
함수형 업데이트(`prev => ...`)는 항상 최신 값을 받는다.

## 3. 종료 — 정리 + 저장

```js
const handleRideStop = useCallback(async () => {
  setIsRiding(false);

  if (rideWatchIdRef.current) {                     // GPS 감시 중지
    navigator.geolocation.clearWatch(rideWatchIdRef.current);
    rideWatchIdRef.current = null;
  }
  if (rideTimerRef.current) {                       // 타이머 중지
    clearInterval(rideTimerRef.current);
    rideTimerRef.current = null;
  }

  if (user?.id && rideDistance > 0) {               // 로그인 + 이동거리 있을 때만 저장
    try {
      const duration = Math.floor(rideTime / 60);   // 분 단위
      await api.post('/api/ride-records', {
        userId: user.id,
        distance: rideDistance / 1000,              // km로 변환
        duration
      });
      showToast(`주행 기록 저장됨! ${(rideDistance / 1000).toFixed(2)}km · ${duration}분`);
    } catch (error) {
      console.error('주행 기록 저장 실패:', error);
      showToast('주행 기록 저장에 실패했습니다.', 'error');
    }
  }

  rideStartPosRef.current = null;
  rideStartTimeRef.current = null;
}, [user?.id, rideTime, rideDistance]);
```

## 4. UI

```jsx
<button
  onClick={isRiding ? handleRideStop : handleRideStart}
  style={{ backgroundColor: isRiding ? '#ef4444' : '#10b981', ... }}
>
  {isRiding ? '라이딩 종료' : '라이딩 시작'}
</button>

{isRiding && (
  <div style={{ fontSize: '12px', color: '#666' }}>
    <div>시간: {Math.floor(rideTime / 60)}:{(rideTime % 60).toString().padStart(2, '0')}</div>
    <div>거리: {(rideDistance / 1000).toFixed(2)}km</div>
  </div>
)}
```

`padStart(2, '0')` 으로 `12:5` 가 아니라 `12:05` 로 보이게 한다.

> 이 부분만 인라인 `style` 을 쓰고 있다. 프로젝트의 나머지는 `App.css` 의 클래스를 쓰므로
> 스타일 방식이 섞여 있다 — 정리 대상.

## 5. 현재 문제와 알아둘 점

| 문제 | 설명 |
|------|------|
| 비로그인은 저장 안 됨 | `if (user?.id && rideDistance > 0)` 조건 — 게스트는 측정만 되고 기록이 남지 않는다 |
| 새로고침하면 사라짐 | 기록이 state에만 있어서 페이지를 벗어나면 진행 중인 라이딩이 초기화된다 |
| 경로가 안 남는다 | 거리 합계만 누적하고 **지나온 좌표를 저장하지 않는다.** 나중에 지도에 그릴 수 없음 |
| watchPosition 중복 | 위치 마커용 감시와 라이딩용 감시가 **동시에 2개** 돈다 (배터리 소모) |
| 백그라운드 정지 | 브라우저 탭이 백그라운드로 가면 타이머와 GPS가 느려지거나 멈춘다 |
| 에러 콜백 없음 | 라이딩용 `watchPosition` 에 두 번째 인자(에러 핸들러)가 없어서 실패해도 조용히 지나간다 |

## 6. 백엔드 — 이름이 어긋나는 문제를 DTO가 흡수한다

```java
// entity/RideRecord.java
@Entity @Table(name = "ride_records") @Data
public class RideRecord {
    @Id @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    private Long userId;
    private Double distanceKm;     // 주행 거리 (km)
    private Integer durationMin;   // 소요 시간 (분)
    private LocalDateTime ridedAt = LocalDateTime.now();
}
```

프론트는 이런 body를 보낸다:
```json
{ "userId": 2, "distance": 4.21, "duration": 34 }
```

이름이 엔티티(`distanceKm`, `durationMin`)와 다르다. 여기서 선택지가 두 개였다.

| 방법 | 장단점 |
|------|--------|
| 프론트를 고쳐 이름을 맞춘다 | 코드가 단순해지지만 **이미 동작하던 화면을 건드려야** 한다 |
| **DTO가 흡수한다** ← 채택 | 프론트를 안 건드림. DTO가 "바깥 세상과 내부 모델 사이의 번역기" 역할을 한다 |

```java
// dto/RideRecordRequest.java — 바깥(프론트)의 이름을 그대로 받는다
@Data
public class RideRecordRequest {
    private Long userId;
    private Double distance;   // km
    private Integer duration;  // 분
}
```

```java
// controller/RideRecordController.java — 여기서 내부 이름으로 옮겨 담는다
@PostMapping
public ResponseEntity<?> save(@RequestBody RideRecordRequest req) {
    if (req.getUserId() == null || req.getDistance() == null) {
        return ResponseEntity.badRequest().body(Map.of("message", "userId, distance는 필수입니다"));
    }
    RideRecord record = new RideRecord();
    record.setUserId(req.getUserId());
    record.setDistanceKm(req.getDistance());                              // ← 번역
    record.setDurationMin(req.getDuration() != null ? req.getDuration() : 0);
    RideRecord saved = rideRecordRepository.save(record);
    return ResponseEntity.ok(Map.of("id", saved.getId(), "message", "주행 기록 저장 완료"));
}

@GetMapping                          // GET /api/ride-records?userId=2
public List<RideRecord> list(@RequestParam Long userId) {
    return rideRecordRepository.findByUserIdOrderByRidedAtDesc(userId);
}
```

**이게 DTO를 쓰는 진짜 이유다.** 엔티티를 그대로 `@RequestBody` 로 받았다면
필드명이 안 맞아 `distanceKm` 이 `null` 로 들어왔을 것이고, 그걸 고치려면
프론트를 바꾸거나 엔티티(=DB 컬럼) 이름을 바꿔야 했다.

`ddl-auto=update` 라서 엔티티만 만들면 `ride_records` 테이블은 서버 시작 시 자동 생성된다.

> `GET /api/ride-records` 는 아직 **어떤 화면에서도 호출하지 않는다.**
> 마이페이지를 만들 때 쓰라고 미리 열어둔 것.
