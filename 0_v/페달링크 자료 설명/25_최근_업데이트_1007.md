## 1. 보유 자전거 → 구글 검색 링크

- 내 프로필(기본 정보 → 보유 자전거)과 다른 사람 프로필 창에서 자전거 이름을 누르면 **새 탭**으로 구글 검색이 열린다.
- 검색어 끝에 "자전거"를 붙인다 (`삼천리 로드` → `삼천리 로드 자전거`). 이름에 이미 "자전거"가 있으면 붙이지 않는다.
- **쉼표로 나눠 자전거마다 따로 링크.** 전각 쉼표(，)도 나누고, 빈 칸·중복 이름은 합친다. 비어 있으면 `-`.
- 다른 사람 프로필 창은 피드·지도 이름표·라이딩 화면이 같이 쓰므로 세 곳 모두 적용.
- 파일: `utils/bike.js`(나누기·주소 만들기), `components/BikeLinks.jsx`, `styles/bikelinks.css`. 프론트만.

## 2. 크루 설정 · 크루 나가기

- **크루 설정 창 (리더만 보임)** — 가입 방식 `approval`(승인 후 가입) / `open`(바로 가입) / `closed`(신청 안 받음) 선택 후 [저장]. 대기 중인 신청의 수락·거절도 이 창 안에서 한다(따로 있던 "가입 요청 관리" 버튼은 없앰).
- `PUT /api/crews/{id}/settings` `{ userId, joinPolicy }` — 리더가 아니면 거부, 세 값 외에는 400.
- `closed` 크루에 신청하면 "지금은 가입 신청을 받지 않는 크루입니다." 크루 찾기 카드는 "신청 마감"으로 막힌다.
- **크루 나가기 창** — 멤버는 [취소]/[크루 나가기] 확인(처음 선택은 취소). 리더는 "리더는 크루를 나갈 수 없어요" 안내만(리더 넘기기 기능은 없음). ESC 로 닫힘.
- 멤버가 나가면 아직 출발 전인 크루 라이딩의 초대·토큰도 같이 지운다.

## 3. 크루 가입 수락·거절 — 리더 확인

- 전에는 `approve`/`reject` 가 요청한 사람을 받지 않아, API 를 직접 부르면 누구나 처리할 수 있었다.
- 이제 body `{ leaderId }` 를 받아 **리더인지**, 그리고 **대기 중인 신청인지** 확인한다. 거절 API 로 이미 가입한 멤버를 내보내는 것도 막힌다.
- 주의: VM 배포 때 **프론트와 백엔드를 같이** 올려야 한다(옛 프론트는 leaderId 를 안 보내 전부 거부됨).

## 4. AI 라이딩 리포트 (Claude) + 그래프 3종

```
프로필 [AI 분석 보기] → POST /api/ride-records/insight?userId=
   ├ DB 기록으로 숫자만 계산 (이름·이메일은 보내지 않음, 최근 30건)
   ├ Claude 호출: 고정 질문 + 숫자 → { level, summary, advice[] } (structured output)
   └ ride_insights 에 저장 — 기록이 그대로면 다음부터 저장분을 돌려줌(재호출 없음)
그래프 ← 이미 받는 라이딩 기록 목록으로 브라우저가 직접 그림 (토큰 없음)
```

- 질문은 **모든 사용자가 같다** — `RideInsightService.QUESTION` (화면 표시용은 `RideReport.jsx` 의 `QUESTION`). 국가대표·프로 선수 훈련법(지구력·인터벌·케이던스·업힐 반복·회복일)을 그 사람 수준에 맞춰 조언하고, 특정 선수의 말·기록은 지어내지 말라고 지시.
- 결과: 수준 배지(입문·초급·중급·상급) + 한줄 요약 + 조언 2~3개. 기록이 바뀌면 "새 기록으로 다시 분석" 버튼.
- `GET /api/ride-records/insight` 는 저장분과 "기록이 바뀌었는지"만 준다(Claude 호출 없음). 기록 0건이면 호출하지 않는다.
- **그래프 탭** (←/→ 키로도 이동, 마우스를 올리면 값 표시, 숫자는 실제 기록)
  - 라이딩 잔디: 최근 1년 하루 한 칸(GitHub 잔디처럼) + 합계 4개(라이딩한 날·총 라이딩·총 거리·최장 연속)
  - 평균 속도: 최근 20회 라이딩별 속도 선 + 평균선
  - 누적 거리: 첫 라이딩부터 계단형 영역
- 1회 약 $0.02 추정 (Opus 5.5, effort `low`). 테이블: `ride_insights` (사용자당 1행 — level·summary·advice(JSON)·ride_count·last_ride_id·model).

## 5. 라이딩 통계 한마디 조언 (Claude)

- 통계 카드의 고정 문구 2줄을 **통계가 늘 때마다 새로 쓰는 한마디 조언**으로 바꿨다.
- 프로필을 열면 지금 통계(횟수·거리·시간·상승고도·산악 완주)를 마지막 조언 때 통계와 비교 → 달라졌으면 "새 조언을 만드는 중…" 후 새 조언, 같으면 저장분을 바로 보여줌.
- Claude 에는 지금·지난번 통계, 그 차이(+1회, +31.6km…), 가장 최근 라이딩, 최근 조언 5개를 보내고 같은 말을 되풀이하지 말라고 지시.
- 기록 없음 · 키 없음 · 생성 실패면 아무것도 안 보인다.
- `GET /api/ride-records/tip` (저장분 + `stale`) / `POST` (stale 일 때 프론트가 부름). 프롬프트: `RideTipService` 의 `QUESTION`·`SYSTEM_PROMPT`. 1회 약 $0.01 추정.
- 테이블: `ride_tips` (사용자당 1행 — tip·그때 통계(JSON)·최근 조언 5개(JSON)·model).

## 6. Claude API 연결 · 키 관리

- 공통 연결 `ClaudeClient` (공식 SDK `com.anthropic:anthropic-java:2.34.0`) — 리포트와 한마디 조언이 같이 쓴다. 모델 `claude-opus-5-5`, 거절 시 다른 모델로 넘기는 `fallbacks: "default"` 켬.
- **키 읽는 곳:** 환경변수 `ANTHROPIC_API_KEY` 또는 `my-app-backend/.env` (`application.properties` 의 `spring.config.import=optional:file:./.env[.properties]`). `.env` 는 `.gitignore`(`**/.env`)로 깃에서 제외. 반드시 `my-app-backend` 폴더에서 실행해야 `.env` 를 찾는다.
- 키가 없으면 AI 기능만 꺼지고 나머지는 그대로 동작.
- **키 검사:** 켜질 때 HTTP 헤더에 못 쓰는 글자(예: 복사하다 바뀐 대시 `U+2011`)가 있으면 몇 번째 글자인지만 로그에 남기고 AI 를 끈다. 앞뒤 공백·따옴표는 자동 제거. **로그에 키 값은 절대 남기지 않는다** (전에는 오류 메시지에 키가 찍혔다).
- **현재 상태:** 키 인증·모델 권한은 정상이지만 계정 **크레딧이 없어** Anthropic 이 `400 credit balance is too low` 로 거절 → 화면엔 "AI 분석에 실패했어요". 충전하면 코드 수정 없이 동작.
- VM: jar 실행 폴더에 `.env` 를 두거나 systemd 에 `Environment=ANTHROPIC_API_KEY=...`.

- 프로필 라이딩 기록을 **한 페이지 10개, 페이지 번호 5개씩 묶어** 보여준다 (`‹ 이전 1 2 3 4 5 다음 ›`, 제목 옆 `1–10 / 156건`).

- 모바일은 [이전]/[다음] 글자 없이 화살표만, 기록 한 줄의 날짜·거리·시간을 코스 이름 아래로 내려 **가로 넘침(15px)도 해결**.
- `components/Pagination.jsx` 는 다른 목록에도 그대로 쓸 수 있다.

## 8. 라이딩 통계 숫자 표시

- 총 거리: 소수 첫째 자리까지, 끝이 `.0` 이면 뗀다 (2560.0 → `2560`).
- 총 시간: 분 → **시간**으로 ("총 시간(h)", 8138분 → `135.6`).
- 다른 사람 프로필 창의 통계도 같은 방식. 함수는 `utils/format.js` 의 `fmt1`, `minutesToHours`.
- 아직 `.0` 이 남은 곳: km당 상승, 라이더 역량의 지구력 (미정).

## 10. 피드 북마크 → 내 코스 목록에 저장

```
피드 카드 북마크 → POST /api/routes/{id}/bookmark { userId } → { bookmarked }
  → 코스 만들기의 "저장된 경로 목록"에 "저장한 코스 · 작성자" 로 섞여 나옴 (GET /api/routes?userId=&includeSaved=true)
  → 누르면 지도에 열림 → [라이딩 시작] (기록에 원래 코스 연결)
```

- 다시 누르면 저장 취소. 내 게시물엔 버튼 없음, 비로그인은 로그인 화면으로. [지도로 보기]는 `/map?route=` 로 바로 열림.
- 목록에서 삭제 `POST /api/routes/delete { userId, ids }` — 내 코스는 삭제, 저장한 남의 코스는 **저장만 취소**.
- **보안 수정:** 전에는 id 만 보내면 누구의 코스든 지워졌다 → 이제 서버가 주인을 확인한다.
- **버그 수정:** 최단 경로가 없는 코스(더미 1만 개 전부)의 상세 조회가 500 이던 문제.
- 글쓰기·파티·크루 라이딩의 코스 고르기는 지금처럼 **내 코스만**.
- 테이블 `route_bookmarks` (user_id, route_id) — 원작자가 코스를 지우거나 탈퇴하면 같이 지워진다(CASCADE).

## 11. [게시물 올리기]를 해야 피드 공개

- 문제: 피드가 `routes` 의 **모든 코스**를 보여줘서, 저장만 한 코스도 피드에 떴다 (처음 설계가 "저장 = 공유", 08-19 `4635a3c` 부터). 오늘 만든 북마크 때문에 남이 저장까지 할 수 있게 되어 고쳤다.
- `routes.published_at` 추가 — [게시물 올리기]를 처음 누를 때 기록. 고쳐 다시 올려도 첫 시각 유지.
- 피드·사이드바·예전 전체 피드·북마크 모두 **올린 코스만**. 피드의 "n시간 전"도 올린 시각 기준.
- 기존 코스: 글이나 태그가 있으면 올린 것으로 처리(공개 10,003개), 저장만 한 4개(`test44`, `123123`, `산`, `유한대 경로`)는 피드에서 빠짐(각자 목록엔 그대로).
- 빈 피드 문구: "코스를 저장한 뒤 [게시물 올리기]로 공유해 보세요". 올린 게시물을 내리는 기능은 아직 없다.

| 참가 요청 관리 | 누구나 API 로 처리 가능 | 방장만 (403) |

- `POST /api/parties/{id}/members/{memberId}/kick` `{ userId(방장) }` — 상태를 `kicked` 로. 꽉 찬(full) 파티면 다시 모집 중(open).
  - 강퇴된 사람은 **같은 파티에 다시 신청 불가**("방장이 내보낸 파티라 다시 신청할 수 없어요."), 근처 파티 목록에서도 안 보인다.
  - `/api/me/status` 에 `kickedParties` 추가 → 강퇴된 사람 화면에 5초 안에 "'파티이름' 파티에서 방장이 내보냈어요." 배너. [확인]을 누르면 다시 안 뜬다(브라우저별 기억 `pl:kickedSeen:{userId}`).
- `PUT /api/parties/{id}/route` `{ userId(방장), routeId }` — 방장 본인 코스만, 끝난 파티·라이딩 중이면 400. 북마크한 남의 코스는 목록에 없다.
- 파티 수락·거절도 body `{ userId(방장) }` 를 받아 방장인지 확인. 권한 오류(SecurityException)는 403, 나머지는 400 + 이유 문구(화면에 그대로 표시).
- 같이 고친 것: 상단 배너가 나타날 때 오른쪽으로 치우쳤다 튀던 애니메이션(매칭 신청 배너 포함), 모바일에서 배너가 메뉴 버튼을 가리던 문제.

## 14. 크루 라이딩 종료 일관성

- 문제: 크루 라이딩에서 [라이딩 종료]를 눌러도 파티는 `full` 로 남고 시작 시각만 지워졌다. 크루 라이딩이 끝났는지는 연결된 파티가 끝났는지로만 판단해서, **새로고침하면 라이딩 화면이 다시 뜨고** 그 크루는 새 라이딩도 못 열었다.
- 수정
  - `stop-ride` 를 **크루 라이딩 파티에 쓰면 파티까지 `ended`**. 일반 파티는 예전처럼 대기방으로 돌아간다.
  - 라이딩 화면 자동 열기(`findMyRiding`)는 실제로 라이딩 중(끝나지 않았고 시작 시각 있음)인 파티만.
  - 파티가 끝나 목록에서 빠져도 기록 팝업은 [확인]까지 유지, 닫은 뒤 끝난 파티의 대기방은 안 연다.
  - 멤버 화면은 파티가 `ended` 여도 종료로 인식하고, 라이딩 중 강퇴되면 라이딩 화면을 닫는다.
- 마이그레이션 **014** — 예전 방식으로 멈춘 채 남은 크루 라이딩 파티를 `ended` 로 정리(스키마 변경 없음). 로컬에선 파티 43("이번주 라이딩")이 정리됨. 되돌리기: `UPDATE parties SET status='full' WHERE id=43;`
