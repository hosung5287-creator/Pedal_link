## 구성 한눈에

```
휴대폰 / PC
    │ HTTPS
Cloudflare Tunnel  ← 수동으로 띄움
    │
┌───┴──────────────────────────┐
│  Rocky Linux VM              │
│  Nginx :80          [자동]   │
│   ├─ /      → 정적 파일       │
│   └─ /api/  → Spring :8080   │
│                 │ localhost  │
│  Spring Boot :8080  [자동]   │
│           PostgreSQL :5432   │  [자동]
└──────────────────────────────┘
      8080 · 5432 외부 차단 (80만 개방)
```

| 구성요소 | 자동 시작 | 비고 |
|---|---|---|
| PostgreSQL | ✅ | `postgresql-18` |
| Spring Boot | ✅ | `pedallink` · 죽으면 5초 뒤 자동 재시작 |
| Nginx | ✅ | |
| **Cloudflare Tunnel** | ❌ | **매번 수동** · 주소가 바뀜 |

---

## 1. 켜기

### VM 재부팅 후

서비스 3개는 자동으로 뜬다. **터널만 띄우면 된다.**

```bash
nohup cloudflared tunnel --url http://localhost:80 > ~/tunnel.log 2>&1 &
sleep 15
grep -o "https://[a-z-]*\.trycloudflare\.com" ~/tunnel.log | head -1
```

나온 주소로 접속하면 끝이다.

> `nohup ... &` 는 **SSH 를 닫아도 계속 돌게** 한다. 그냥 실행하면 창을 닫는 순간 죽는다.

### 연결됐는지 확인

```bash
grep -c "Registered tunnel connection" ~/tunnel.log
```

`1` 이상이면 살아있다.

---

## 2. 끄기

### 터널만

```bash
pkill -f "cloudflared tunnel"
pgrep -af cloudflared          # 아무것도 안 나와야 함
```

### 서비스

```bash
sudo systemctl stop pedallink
sudo systemctl stop nginx
sudo systemctl stop postgresql-18
```

> ⚠️ **백엔드는 `pkill` 로 끄면 안 된다.** `Restart=always` 라서 5초 뒤 되살아난다.
> 반드시 `systemctl stop` 을 쓴다.

### VM 전체

```bash
sudo poweroff
```

## 3. 상태 점검

```bash
# 서비스 3개
sudo systemctl is-active postgresql-18 pedallink nginx

# 포트
sudo ss -tlnp | grep -E ':80|:8080|:5432'

# 터널
pgrep -af cloudflared

# 응답
curl -I http://localhost/
curl http://localhost/api/crews
```

### 정상일 때 보이는 것

```
active        ← 3줄
active
active

LISTEN  *:80              nginx
LISTEN  *:8080            java
LISTEN  127.0.0.1:5432    postgres     ← localhost 만. 정상
```

`5432` 가 `*:5432` 로 보이면 **외부에 열린 것이니 즉시 막아야 한다.**

## 5. 코드를 고쳤을 때 — 재배포

절차가 길어 **[23_배포_업데이트_가이드.md](23_배포_업데이트_가이드.md) 로 분리**했다.

| 고친 것 | 요약 |
|---|---|
| 프론트 | `npm run build` → scp → `cp` + `restorecon` · **재시작 불필요** |
| 백엔드 | `bootJar` → scp(다른 이름) → `stop` → 교체 → `start` |
| 엔티티(스키마) | 위 + `ddl-auto=update` 한 번 → 확인 → `validate` 복귀 |
| Nginx 설정 | `nginx -t` → `systemctl reload nginx` |

> ⚠️ **돌아가는 중에 JAR 을 덮어쓰지 말 것.** Spring Boot 는 클래스를 그때그때 JAR 에서
> 꺼내 쓰므로 `NoClassDefFoundError` 가 난다. 멈춘 뒤에 교체한다.

## 6. 문제 해결

### 화면이 안 뜬다

```bash
sudo systemctl status nginx
sudo nginx -t
curl -I http://localhost/
```

| 증상 | 원인 | 조치 |
|---|---|---|
| **403** Forbidden | SELinux 라벨 | `sudo restorecon -Rv /var/www/pedallink` |
| **404** (nginx 페이지) | 설정 미반영 | `sudo systemctl reload nginx` |
| **502** Bad Gateway | 백엔드 꺼짐 또는 SELinux | 아래 참고 |

### 502 Bad Gateway

```bash
sudo systemctl status pedallink                    # 백엔드 살아있나
sudo getsebool httpd_can_network_connect           # on 이어야 함
sudo setsebool -P httpd_can_network_connect 1      # off 면 켠다
```

### API 만 실패한다

```bash
curl http://localhost:8080/api/crews    # 백엔드 직접 — 여기서 되면 nginx 문제
sudo nginx -T 2>/dev/null | grep -A6 "location /api/"
```

`proxy_pass` 끝에 **슬래시가 붙으면 안 된다.**

```nginx
proxy_pass http://127.0.0.1:8080;     ✅ /api/crews → /api/crews
proxy_pass http://127.0.0.1:8080/;    ❌ /api/crews → /crews
```

### 채팅만 안 된다

WebSocket 헤더 문제다.

```bash
sudo nginx -T 2>/dev/null | grep -A8 "location /ws/"
```

이 세 줄이 있어야 한다.

```nginx
proxy_http_version 1.1;
proxy_set_header Upgrade $http_upgrade;
proxy_set_header Connection "upgrade";
```

### 터널 주소가 530 을 준다

터널이 끊긴 것이다. 주소는 살아있지만 연결이 없다는 뜻.

```bash
pgrep -af cloudflared     # 없으면 죽은 것
nohup cloudflared tunnel --url http://localhost:80 > ~/tunnel.log 2>&1 &
```

**새 주소가 발급된다.** 이전 주소는 재사용할 수 없다.

### 백엔드가 계속 재시작한다

```bash
sudo journalctl -u pedallink -n 50 --no-pager
```

| 메시지 | 원인 |
|---|---|
| `password authentication failed` | 서비스 파일의 비밀번호가 DB 와 다름 |
| `Schema-validation: missing column` | `validate` 인데 컬럼이 없음 → 한 번 `update` |
| `No such file or directory` | `ExecStart` 의 JAR 경로 오류 |
| `Changing to the requested working directory failed` | `WorkingDirectory` 경로 오류 |

비밀번호를 모르면 다시 정하면 된다.

```bash
sudo -u postgres psql -c "ALTER USER postgres PASSWORD '새비밀번호';"
# 서비스 파일에도 같은 값을 넣고 daemon-reload → restart
```

## 7. 발표 당일 절차

### 시작 30분 전

```bash
# ① VM 켜고 SSH 접속 후
sudo systemctl is-active postgresql-18 pedallink nginx
# active 3줄 확인

# ② 로컬 응답 확인
curl -I http://localhost/
curl http://localhost/api/crews

# ③ 터널 띄우기
nohup cloudflared tunnel --url http://localhost:80 > ~/tunnel.log 2>&1 &
sleep 15
grep -o "https://[a-z-]*\.trycloudflare\.com" ~/tunnel.log | head -1
```

### 체크리스트

- ☐ 서비스 3개 `active`
- ☐ 터널 주소가 PC 브라우저에서 열리는가
- ☐ 로그인 → 경로 저장 → 목록 조회
- ☐ 파티 생성 → 참가 → 승인
- ☐ 크루 만들기 · 크루 채팅
- ☐ **휴대폰**에서 GPS 가 잡히는가
- ☐ 지오펜싱 시뮬레이터 (`/geofence-test.html`)

> **위치 시연은 반드시 휴대폰으로.** 데스크톱 PC 는 GPS 가 없어 IP 로 추정하므로
> 수 km 씩 어긋난다. 지오펜스 반경이 50m 라 판정이 무의미해진다.

### 주의

| 항목 | 내용 |
|---|---|
| 터널 창 | `nohup` 으로 띄웠으면 SSH 닫아도 되지만, **VM 을 끄면 죽는다** |
| 터널 주소 | 띄울 때마다 바뀐다. **미리 공유 불가** |
| VM IP | DHCP 라 재부팅 시 바뀔 수 있다 (`ip a` 로 확인) |

## 8. 자주 쓰는 명령 모음

```bash
# 상태
sudo systemctl is-active postgresql-18 pedallink nginx
sudo ss -tlnp | grep -E ':80|:8080|:5432'
pgrep -af cloudflared

# 터널
nohup cloudflared tunnel --url http://localhost:80 > ~/tunnel.log 2>&1 &
grep -o "https://[a-z-]*\.trycloudflare\.com" ~/tunnel.log | head -1
pkill -f "cloudflared tunnel"

# 재시작
sudo systemctl restart pedallink
sudo systemctl reload nginx        # 설정만 다시 읽기 (무중단)
sudo systemctl restart nginx       # 완전 재시작

# 로그
sudo journalctl -u pedallink -f
sudo tail -30 /var/log/nginx/error.log

# DB
sudo -u postgres psql -d Pedal_link
sudo -u postgres psql -d Pedal_link -c "SELECT COUNT(*) FROM users;"
```

---

## ⚠️ 하면 안 되는 것

| 금지 | 이유 |
|---|---|
| `sudo nginx` 직접 실행 | systemd 와 별개로 또 뜬다. `systemctl` 만 쓸 것 |
| `pkill -f pedallink.jar` | `Restart=always` 로 되살아난다. `systemctl stop` 을 쓸 것 |
| `psql -U postgres` | `peer` 인증 실패. `sudo -u postgres psql` 을 쓸 것 |
| `dnf ... \| grep ...` | dnf 의 질문이 가려져 멈춘 것처럼 보인다 |
| `scp` 에서 콜론 생략 | 원격 전송이 아니라 로컬 복사가 된다 |
