## 최종 구성

```
                    인터넷 / 휴대폰
                          │
              Cloudflare Tunnel (HTTPS)
                          │
┌─────────────────────────┼──────────────────────────┐
│  Rocky Linux 10 VM      ▼                          │
│                    Nginx :80                       │
│                  ┌──────┴───────┐                  │
│           /      │              │  /api/  /ws/     │
│           ▼      │              ▼                  │
│    /var/www/pedallink     Spring Boot :8080        │
│    (빌드된 프론트)               │ localhost        │
│                                 ▼                  │
│                        PostgreSQL :5432 + PostGIS  │
└────────────────────────────────────────────────────┘
        8080 · 5432 는 외부에 열지 않음 (80만 개방)
```

### 왜 이 구성인가

| 항목 | 이유 |
|------|------|
| 전부 같은 VM에 | DB↔백엔드가 `localhost`라 **끊길 네트워크 구간이 없음** |
| Nginx가 프론트와 API를 한 포트로 | **CORS 자체가 발생하지 않음** — 같은 출처이므로 |
| 터널 1개 | 발표 당일 점검할 곳이 한 군데 |
| 5432·8080 미개방 | 방화벽 실수 여지를 원천 차단 |
| 윈도우 불필요 | VM만 켜면 PC·휴대폰 모두 접속 가능 |

## ⚠️ 0단계 — 가장 먼저 확인할 것

**이것부터 확인하지 않으면 8단계에서 막힙니다.**

현재 로컬 DB는 **PostgreSQL 18.3 + PostGIS 3.6** 입니다. 그런데 Rocky 10 기본 저장소에는 **PostgreSQL 16**밖에 없습니다.

> **PostgreSQL은 낮은 버전 → 높은 버전 복원만 지원합니다.**
> PG18에서 뽑은 덤프는 PG16에 들어가지 않습니다.

VM을 만든 뒤 가장 먼저 이 명령을 실행하세요.

```bash
# PGDG 저장소 추가
sudo dnf install -y https://download.postgresql.org/pub/repos/yum/reporpms/EL-10-x86_64/pgdg-redhat-repo-latest.noarch.rpm

# GPG 키 등록 — 이걸 건너뛰면 다음 단계에서 서명 오류가 난다
sudo rpm --import /etc/pki/rpm-gpg/PGDG-RPM-GPG-KEY-RHEL
rpm -q gpg-pubkey --qf '%{summary}\n' | grep -i postgres   # PostgreSQL 줄이 나와야 정상

# 저장소 목록 받기 (1~2분, 끊지 말 것)
sudo dnf makecache

# 18 버전 패키지가 있는지 확인
dnf list available postgresql18-server postgis36_18
```

### ✅ 확인 결과 (2026-09-18)

**Rocky 10용 PG18 패키지가 존재합니다.** 경로 A로 진행하면 됩니다.

```
postgresql18-server.x86_64   18.6-4PGDG.rhel10.2   pgdg18
postgis36_18.x86_64          3.6.4-1PGDG.rhel10.2  pgdg18
```

| | 로컬 | VM |
|---|------|-----|
| PostgreSQL | 18.3 | 18.6 |
| PostGIS | 3.6 | 3.6.4 |

같은 메이저 버전이고 VM 쪽이 더 최신이라 **덤프가 그대로 복원됩니다.**

### ⚠️ dnf 명령에 `| grep` 을 쓰지 말 것

```bash
dnf list available | grep "postgresql18"     # ❌ 멈춘 것처럼 보임
dnf list available postgresql18-server       # ✅
```

dnf는 GPG 키 신뢰 여부 같은 걸 중간에 묻는데, **파이프로 grep에 넘기면 그 질문이 화면에 안 보입니다.**
답을 기다리며 멈춰 있는데 아무것도 안 뜨니 "응답이 없다"고 오해하기 쉽습니다.
조회할 땐 grep 대신 **dnf 자체 필터**(명령 뒤에 패키지명)를 쓰세요.

### 경로 B — PG18 패키지가 없을 때

발표까지 시간이 촉박하다면 **DB만 윈도우에 남기는 것**이 가장 안전합니다. 백엔드만 VM에 올리고 `spring.datasource.url`을 윈도우 IP로 지정하는 구성입니다. 다만 이 경우 윈도우 쪽 PostgreSQL을 외부 접속 허용으로 바꿔야 하므로, 시간이 있다면 아래를 먼저 시도하세요.

```bash
# 17 버전이라도 있는지 확인 (18 → 17 도 복원 불가이므로 참고용)
dnf list available | grep postgresql1
```

**PG16으로 내려가야 한다면** 로컬에서 스키마를 다시 만들어야 합니다. 단순 덤프로는 안 되고, 마이그레이션 SQL을 PG16 DB에 순서대로 실행한 뒤 데이터만 옮기는 방식이 필요합니다. 이 경우 별도로 상의해 주세요.

### 권장 사양

| 항목 | 값 | 비고 |
|------|-----|------|

### VM 설정에서 꼭 확인할 것

Rocky 10(RHEL 10 계열)은 **x86-64-v3** CPU를 요구합니다. Ryzen 5 7430U는 지원하지만, VM이 CPU 기능을 가리면 설치가 실패합니다.

```
VMware 설정 → 하드웨어 호환성을 최신 버전으로
설치 화면이 안 뜨고 "CPU does not support x86-64-v3" 가 나오면 이 문제
```

## 2단계 — SSH 접속 뚫기

VM 콘솔에서는 **복사·붙여넣기가 안 됩니다.** 이후 작업이 전부 명령어 입력이므로 SSH부터 뚫습니다.

VM 콘솔에서 직접 입력 (여기까지만 수동):

```bash
ip a                        # 192.168.x.x 주소 확인
systemctl status sshd       # active (running) 확인
```

꺼져 있으면:

```bash
sudo systemctl enable --now sshd
sudo firewall-cmd --permanent --add-service=ssh
sudo firewall-cmd --reload
```

윈도우 PowerShell에서:

```powershell
ssh user1@192.168.x.x
```

> VMware NAT를 쓰면 호스트에 `VMware Network Adapter VMnet8`이 있어 **포트포워딩 없이 바로 접속됩니다.**

### VM으로 전송 후 복원

**전송과 복원은 서로 다른 창에서 합니다.**

| 단계 | 실행 위치 | 이유 |
|------|-----------|------|
| `pg_dump` | **PowerShell** (윈도우) | 원본 DB가 윈도우에 있음 |
| `scp` | **PowerShell** (윈도우) | 보낼 파일이 윈도우에 있음 |
| `psql` 복원 | **SSH 창** (VM) | 받을 DB가 VM에 있음 |

SSH 창은 이미 VM 내부라 윈도우 파일이 보이지 않습니다. 거기서 `cd c:\Users\...` 를 치면 실패합니다.

```powershell
# [PowerShell] 전송
scp dump-new.sql user1@192.168.x.x:~/
```

> ### ⚠️ `:~/` 의 콜론을 빠뜨리지 말 것
>
> ```powershell
> scp dump-new.sql user1@192.168.x.x       # ❌ 로컬 복사가 됨
> scp dump-new.sql user1@192.168.x.x:~/    # ✅ 원격 전송
> ```
>
> 콜론이 없으면 scp가 **"user1@192.168.x.x 라는 이름의 파일로 복사"** 로 해석합니다.
> `1 file(s) copied` 가 떠서 성공한 것처럼 보이지만 VM에는 아무것도 가지 않습니다.
>
> **구분법: 비밀번호를 물어보면 원격으로 가고 있는 것입니다.** 안 물어보면 로컬 복사입니다.

```bash
# [SSH 창] 도착 확인 후 복원
ls -la ~/dump-new.sql
sudo -u postgres psql -d Pedal_link < ~/dump-new.sql > /tmp/restore.log 2>&1
echo "오류 건수: $(grep -ci error /tmp/restore.log)"
```

> ### ⚠️ `sudo -u postgres` 를 반드시 붙일 것
>
> ```bash
> psql -U postgres -d Pedal_link              # ❌ peer 인증 실패
> sudo -u postgres psql -d Pedal_link         # ✅
> ```
>
> PostgreSQL 기본 설정은 **`peer` 인증** 입니다. 비밀번호를 보지 않고
> **리눅스 계정 이름과 DB 계정 이름이 같은지만** 확인합니다.
> `user1` 로 로그인한 상태에서 `-U postgres` 를 쓰면 이름이 달라 거부됩니다.
>
> ```
> psql: 오류: ... 사용자 "postgres"의 peer 인증을 실패했습니다
> ```
>
> `sudo -u postgres` 는 명령을 실행하는 **리눅스 계정 자체를 `postgres` 로 바꿔** 이름을 맞춰줍니다.
> 이미 `postgres` 로 실행 중이므로 `-U postgres` 는 생략해도 됩니다.
>
> **`-f` 대신 `<` 를 쓰는 이유:** `-f` 는 `postgres` 계정이 `/home/user1/` 을 직접 읽어야 하는데
> 홈 디렉터리 권한에 막힐 수 있습니다. `<` 는 파일 읽기를 `user1` 쉘이 대신 처리합니다.

### ⚠️ `ddl-auto` 설정 주의

| 값 | 동작 | 권장 |
|----|------|------|
| `update` | 엔티티에 맞춰 컬럼을 **자동 추가** | ❌ |
| `validate` | 불일치하면 **기동 실패** | ✅ |

`update`를 피하는 이유는 실제로 사고가 있었기 때문입니다. `party_members`에 기존 행이 있는 상태에서 `ready BOOLEAN NOT NULL`을 DEFAULT 없이 추가하려다 실패했는데, **Hibernate가 WARN만 남기고 정상 기동해서** 한참 뒤에야 발견됐습니다.

`validate`는 불일치를 **기동 시점에 즉시 드러냅니다.** 발표 당일에 조용히 깨져 있는 것보다 훨씬 낫습니다.

> `validate`로 기동이 실패하면 DB와 엔티티가 어긋난 것입니다. 5단계 덤프가 최신인지 먼저 확인하세요.

## 11단계 — Nginx 설치·설정 (VM)

```bash
sudo dnf install -y nginx
```

### 정적 파일 배치

```bash
sudo mkdir -p /var/www/pedallink
sudo cp -r ~/front/* /var/www/pedallink/
sudo chown -R nginx:nginx /var/www/pedallink
sudo restorecon -Rv /var/www/pedallink     # SELinux 라벨 — 없으면 403
```

### 설정 파일

```bash
sudo vim /etc/nginx/conf.d/pedallink.conf
```

```nginx
server {
    listen 80;
    server_name _;
    root /var/www/pedallink;
    index index.html;

    client_max_body_size 50M;      # 이미지 업로드 대비

    # SPA — 새로고침해도 404 안 나게
    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto https;
    }

    # WebSocket (채팅) — 이 3줄이 빠지면 채팅만 안 된다
    location /ws/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_read_timeout 3600s;
    }
}
```

### SELinux · 방화벽

```bash
# 이거 없으면 무조건 502 — Nginx 가 8080 으로 못 나간다
sudo setsebool -P httpd_can_network_connect 1

sudo nginx -t                    # 문법 검사
sudo systemctl enable --now nginx

sudo firewall-cmd --permanent --add-service=http
sudo firewall-cmd --permanent --remove-port=8080/tcp   # 이제 불필요
sudo firewall-cmd --reload
```

### 확인

```bash
curl http://localhost/              # index.html 이 나와야 함
curl http://localhost/api/crews     # JSON 이 나와야 함
```

| 증상 | 원인 |
|------|------|
| 403 Forbidden | SELinux 라벨 — `restorecon` 누락 |
| 502 Bad Gateway | `httpd_can_network_connect` 누락, 또는 백엔드 꺼짐 |
| 화면은 뜨는데 API 만 실패 | `location /api/` 블록 확인 |
| 채팅만 안 됨 | `location /ws/` 의 Upgrade 헤더 3줄 확인 |
