# 둘러보기 — 라이더 피드

> 저장된 경로를 인스타그램 형태의 피드 카드로 보여주는 화면. 경로 `/browse`.
> 홈 상단 네비게이션의 **"둘러보기"** 를 누르면 들어간다.

## 카드 한 장의 구성

```
┌──────────────────────────────────┐
│ (K)  라이더김                      │  ← 아바타(이름 첫 글자) + 작성자
│      📍 잠실                       │  ← 출발지 라벨
├──────────────────────────────────┤
│                                  │
│        ╱‾‾‾●                     │  ← 저장된 좌표로 그린 SVG 경로
│    ●__╱                          │     초록 = 출발, 빨강 = 도착
├──────────────────────────────────┤
│ 📍15.2km    ⛰45m    🕐1시간 20분   │  ← BRouter 분석값
├──────────────────────────────────┤
│ ♡  💬  ↗                      🔖 │  ← 좋아요만 동작, 나머지는 비활성
├──────────────────────────────────┤
│ 2 likes                          │
│ 라이더김 한강 야경 라이딩            │
│ 잠실에서 여의도까지 이어지는 코스입니다. │
│ #초보코스 #잠실 #여의도             │
└──────────────────────────────────┘
```

## 1. 썸네일을 지도가 아니라 SVG로 그린 이유

피드에 카드가 20장이면 지도를 20개 띄우게 된다. Leaflet 인스턴스 20개 + 타일 이미지
수백 장을 받아야 해서 매우 무겁다.

대신 **저장된 좌표만 받아서 SVG 선 하나로 그린다.** 네트워크 요청이 0이고,
카드가 몇 장이든 비용이 거의 늘지 않는다.

### 좌표 → 화면 좌표 변환 (RouteThumbnail.js)

세 가지를 해결해야 한다.

**① 위도/경도의 스케일이 다르다**
경도 1도는 위도 1도보다 짧다 (위도에 따라 `cos` 배). 보정하지 않으면 경로가 가로로 찌그러진다.

```js
const midLat = (minLat + maxLat) / 2;
const lngScale = Math.cos((midLat * Math.PI) / 180);   // 서울(37.5도) ≈ 0.79
const spanX = (maxLng - minLng) * lngScale;
```

**② SVG는 y축이 아래로 증가한다**
위도는 위로 갈수록 커지므로 뒤집어야 한다.

```js
y: offsetY + (maxLat - p.lat) * scale     // maxLat 에서 빼면 위아래가 맞는다
```

**③ 가로세로 비율을 유지하며 박스에 맞춘다**
`Math.min` 으로 스케일을 정하면 긴 쪽이 박스에 딱 맞고, 짧은 쪽은 여백이 남는다.
그 여백의 절반씩 밀어서 가운데 정렬한다.

```js
const scale = Math.min(boxW / spanX, boxH / spanY);
const offsetX = PADDING + (boxW - spanX * scale) / 2;
```

`Math.max(..., 1e-9)` 로 span의 0을 막는 것도 중요하다 — 출발지와 도착지가
완전히 같은 경로가 들어오면 `0/0 = NaN` 이 되어 선이 사라진다.

## 2. 좌표 솎아내기 — 서버에서 미리 줄인다

경로 하나가 수천 점이다. 피드에 20장이면 수만 점을 내려보내게 된다.
썸네일은 작아서 60점이면 충분하므로 **서버에서 일정 간격으로 골라낸다.**

```java
// FeedService.thumbnailPath()
int step = Math.max(1, coords.length / THUMBNAIL_POINTS);   // THUMBNAIL_POINTS = 60
for (int i = 0; i < coords.length; i += step) points.add(toPoint(coords[i]));

// 마지막 점은 반드시 넣는다 — 안 그러면 선이 도착지 직전에서 끊긴다
Coordinate last = coords[coords.length - 1];
if (마지막이 빠졌으면) points.add(toPoint(last));
```

`step` 으로 건너뛰면 마지막 점이 딱 맞아떨어지지 않는 경우가 대부분이라,
**끝점을 따로 챙기는 처리가 반드시 필요하다.**

## 3. N+1 쿼리를 피한 방법

피드 1장마다 (작성자 이름 조회 + 좋아요 수 조회)를 하면 경로 20개에 쿼리가 40번 넘게 나간다.
그래서 **한 번에 모아서 조회하고 메모리에서 합친다.**

```java
// ① 작성자 이름 — id 목록을 모아 한 번에
Set<Long> authorIds = routes.stream().map(Route::getUserId).filter(Objects::nonNull).collect(toSet());
Map<Long, String> authorNames = userRepository.findAllById(authorIds).stream()
        .collect(Collectors.toMap(User::getId, User::getName));

// ② 좋아요 수 — GROUP BY 한 방
@Query("SELECT l.routeId, COUNT(l) FROM RouteLike l GROUP BY l.routeId")
List<Object[]> countGroupedByRouteId();

// ③ 내가 좋아요한 경로 id — 한 번에
@Query("SELECT l.routeId FROM RouteLike l WHERE l.userId = :userId")
List<Long> findRouteIdsByUserId(Long userId);
```

경로가 몇 개든 **쿼리는 총 4번**이다 (경로 + 작성자 + 좋아요수 + 내좋아요).

> `Map.getOrDefault` 로 없는 값을 메꾼다. 탈퇴했거나 userId가 `null` 인 옛날 경로는
> `"익명 라이더"` 로 표시된다.

## 4. 좋아요 — 토글과 낙관적 업데이트

### 백엔드: 있으면 지우고 없으면 넣는다

```java
@Transactional
public Map<String, Object> toggleLike(Long routeId, Long userId) {
    var existing = routeLikeRepository.findByRouteIdAndUserId(routeId, userId);
    if (existing.isPresent()) { routeLikeRepository.delete(existing.get()); liked = false; }
    else { /* 새 RouteLike 저장 */ liked = true; }
    return Map.of("liked", liked, "likeCount", routeLikeRepository.countByRouteId(routeId));
}
```

**갱신된 개수를 같이 돌려주는 것**이 포인트다. 프론트가 직접 세지 않고 서버 값을 쓴다
(파티 기능이 갱신된 파티 전체를 돌려주는 것과 같은 발상 — [12](12_파티_링크_기능.md)).

중복 방지는 코드 검사 + `@UniqueConstraint(columnNames = {"route_id", "user_id"})` 두 겹이다.

### 프론트: 하트를 먼저 칠하고 나중에 맞춘다

```js
const handleLike = async (routeId) => {
  const before = items;                       // 실패 시 되돌릴 스냅샷

  setItems(prev => prev.map(it => it.id === routeId    // ① 즉시 반영
    ? { ...it, liked: !it.liked, likeCount: it.likeCount + (it.liked ? -1 : 1) }
    : it));

  try {
    const res = await toggleLike(routeId, user.id);
    setItems(prev => prev.map(it => it.id === routeId   // ② 서버 값으로 확정
      ? { ...it, liked: res.liked, likeCount: res.likeCount } : it));
  } catch {
    setItems(before);                                   // ③ 실패하면 원상복구
  }
};
```

이걸 **낙관적 업데이트(optimistic update)** 라고 한다. 서버 응답을 기다렸다가 칠하면
하트가 0.3초쯤 늦게 반응해서 답답하게 느껴진다. 위치공유 토글도 같은 방식이다
([11](11_지오펜싱_테스트_구현코드.md) 5-6절).

**되돌릴 스냅샷(`before`)을 반드시 잡아둬야 한다.** 안 그러면 실패했을 때
잘못된 하트가 그대로 남는다.

## 5. 게시물 올리기 (작성 모달)

우상단 **"게시물 올리기"** 버튼 → `ComposePostModal` 이 열린다.

```
[경로 선택 ▾]  ← 내 저장 경로 (GET /api/routes?userId=)
[문구        ]  ← 최대 500자
[해시태그    ]  ← "#야경 #초보코스" 또는 "야경, 초보코스"
        [취소] [올리기]
```

### 게시물을 위한 테이블을 따로 만들지 않았다

이 프로젝트에서 **게시물 = 저장된 경로 + 문구/태그**다. 그래서 `posts` 테이블 대신
`routes` 에 컬럼 두 개를 붙였다.

```java
@Column(length = 500) private String description;   // 문구
@Column(length = 300) private String tags;          // "야경,초보코스,한강"
```

경로 하나에 게시물이 여러 개 달릴 일이 없으므로 1:1 관계고, 1:1이면 **테이블을 나누는 것보다
같은 행에 두는 편이 조회가 단순**하다 (조인이 없다).

> 태그를 쉼표로 이어 한 컬럼에 넣은 것은 지금 규모에서의 타협이다.
> "#야경 태그로 검색" 같은 기능이 필요해지면 `route_tags` 테이블로 분리해야 한다.
> 한 컬럼에 여러 값을 넣으면 인덱스를 못 쓰기 때문이다.

### 입력을 정규화한다

사용자는 `#야경 #초보코스`, `야경, 초보코스`, `##야경,,한강` 등 아무렇게나 쓴다.
저장 전에 서버가 한 가지 모양으로 정리한다.

```java
private String normalizeTags(String raw) {
    return Arrays.stream(raw.split("[,\s]+"))   // 쉼표와 공백 아무거나로 자르고
            .map(t -> t.replaceAll("^#+", "").trim())  // 앞의 # 제거
            .filter(t -> !t.isEmpty())
            .distinct()                                 // 중복 제거
            .limit(10)                                  // 개수 제한
            .collect(Collectors.joining(","));
}
```

실제 동작: `"한강, ##야경,,  초보코스 한강"` → `["한강", "야경", "초보코스"]`

**정규화는 반드시 서버에서 한다.** 프론트에서만 정리하면 API를 직접 호출하는 요청은 걸러지지 않는다.

### 본인 확인

```java
if (route.getUserId() == null || !route.getUserId().equals(userId)) {
    throw new SecurityException("본인이 저장한 경로만 올릴 수 있습니다");
}
```
컨트롤러가 이 예외를 **403 Forbidden** 으로 바꾼다. "잘못된 요청(400)"이 아니라
"권한 없음(403)"이 의미상 맞다.

> 다만 `userId` 를 요청 body에서 그대로 받으므로 **남의 userId를 적으면 통과한다.**
> 진짜 방어가 되려면 토큰에서 userId를 꺼내야 한다 ([07](07_Spring_Security.md)).

### 올린 뒤 화면 갱신

응답으로 **갱신된 카드 1장**이 오므로, 목록을 다시 부르지 않고 맨 앞에 꽂는다.

```js
const handlePublished = (card) => {
  setItems(prev => [card, ...prev.filter(it => it.id !== card.id)]);  // 이미 있으면 교체
  window.scrollTo({ top: 0, behavior: 'smooth' });
};
```
`filter` 로 같은 id를 걸러내는 것이 포인트다. 이미 피드에 있던 경로에 문구를 새로 붙이면
**중복 카드가 생기기 때문**이다.

## 6. 문구·태그가 없으면 자동으로 만든다

작성 모달을 거치지 않은 경로(예전에 저장한 것)도 피드에 나온다.
그때는 **있는 값에서 유도**한다.

```jsx
// 태그: 쓴 게 있으면 그걸, 없으면 유도
const tags = item.tags?.length ? item.tags : buildTags(item);

// 문구: 쓴 게 있으면 그걸, 없으면 유도
{item.description ? <p>{item.description}</p>
 : <p>{item.fromLabel}에서 {item.toLabel}까지 이어지는 코스입니다.</p>}
```

| 화면 요소 | 어디서 나오나 |
|-----------|--------------|
| 아바타 글자 | `authorName` 첫 글자 |
| 위치 | `fromLabel` |
| 설명 문구 | `description` 이 없을 때 → `"{fromLabel}에서 {toLabel}까지 이어지는 코스입니다."` |
| 해시태그 | `tags` 가 없을 때 → 거리 구간 + 출발지 + 도착지 |

```js
function buildTags({ distanceKm, fromLabel, toLabel }) {
  const tags = [];
  if (distanceKm <= 10) tags.push('가벼운코스');
  else if (distanceKm <= 25) tags.push('초보코스');
  else if (distanceKm <= 50) tags.push('중급코스');
  else tags.push('장거리');
  ...
}
```

이 방식의 장점: 옛날에 저장한 경로도 **빈 카드로 보이지 않는다.**

## 6. 상승고도·시간은 어떻게 채워지나

카드의 `45m`, `1시간 20분` 은 BRouter 분석값이다. 경로를 저장할 때 거리와 함께 보낸다.

```js
// MapPage.js — confirmSaveRoute
distanceKm: routeStats?.distanceKm ?? null,
ascendM:    routeStats?.ascendM    ?? null,
timeMin:    routeStats?.timeMin    ?? null,
```

`routeStats` 는 `parseBrouterStats()` 결과다 ([14_경로_분석.md](14_경로_분석.md)).
**이 기능이 생기기 전에 저장된 경로는 셋 다 `null`** 이라 카드에 `-` 로 표시된다.

### 컬럼명 함정 하나

`ascendM` 필드를 그냥 두면 Hibernate가 컬럼을 **`ascendm`** 으로 만든다
(`distance_km`, `time_min` 과 달리 끝에 붙은 대문자 한 글자는 밑줄이 안 생긴다).
그래서 명시했다.

```java
@Column(name = "ascend_m")
private Integer ascendM;
```
