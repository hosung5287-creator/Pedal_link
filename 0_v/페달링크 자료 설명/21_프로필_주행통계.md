# 프로필 · 주행 통계

## 이 프로젝트에서 쓰인 곳
- `/profile` 화면 — 소개·자전거 정보·지역·성별·연령 설정
- 누적 주행 통계 (횟수·거리·시간)

## users 테이블에 추가된 컬럼

```java
// entity/User.java — 프로필 기본 정보
private String profileImageUrl;
private String bio;
private String bikeInfo;

// male | female | none
private String gender;
private Integer age;
private String region;
```

**전부 nullable 이다.** 기존 사용자가 있는 상태에서 컬럼을 추가해야 했기 때문이다.

> `ddl-auto=update` 는 기존 행이 있는 테이블에 `NOT NULL` 컬럼을 **기본값 없이** 추가하지 못한다.
> 실패해도 WARN 만 남기고 정상 기동해서 발견이 늦어진다 — [06_PostgreSQL_PostGIS.md](06_PostgreSQL_PostGIS.md) 참고.
> 객체 타입(`String`·`Integer`)을 쓰면 nullable 이 되어 이 문제를 피한다.

`Integer age` 를 `int` 가 아니라 **객체 타입**으로 둔 것도 같은 이유다. `int` 는 `NOT NULL` 이 된다.

## 부분 업데이트 (PATCH 방식)

`controller/UserController.java`

```java
// 보낸 필드만 반영한다 — null 로 온 필드는 기존 값을 그대로 둔다
@PutMapping("/{id}/profile")
public ResponseEntity<?> updateProfile(@PathVariable Long id, @RequestBody ProfileUpdateRequest req) {
    User user = userRepository.findById(id).orElse(null);
    if (user == null) {
        return ResponseEntity.status(404).body(Map.of("message", "사용자를 찾을 수 없습니다."));
    }

    if (req.getProfileImageUrl() != null) user.setProfileImageUrl(req.getProfileImageUrl());
    if (req.getBio() != null)             user.setBio(req.getBio());
    if (req.getBikeInfo() != null)        user.setBikeInfo(req.getBikeInfo());
    if (req.getGender() != null)          user.setGender(req.getGender());
    if (req.getAge() != null)             user.setAge(req.getAge());
    if (req.getRegion() != null)          user.setRegion(req.getRegion());

    userRepository.save(user);
    return ResponseEntity.ok(UserProfileResponse.from(user));
}
```

**`if (… != null)` 을 일일이 쓰는 이유.** 그냥 대입하면 화면에서 보내지 않은 필드가 `null` 로 덮인다.

```
소개만 수정  →  { "bio": "새 소개" }        ← 나머지는 안 보냄
             ↓
if 없이 대입하면 bikeInfo·region 등이 전부 null 이 됨
```

`PUT` 은 원래 "전체 교체" 의미지만, 여기서는 **보낸 것만 바꾸는 PATCH 방식**으로 동작한다.

## 로그인 응답이 바뀐 점 ⚠️

`controller/AuthController.java`

```java
// 이전
return ResponseEntity.ok(Map.of(
    "id", user.getId(), "name", user.getName(),
    "email", user.getEmail(), "locationShareEnabled", user.isLocationShareEnabled()));

// 현재
return ResponseEntity.ok(UserProfileResponse.from(user));
```

프론트는 로그인 응답을 **`localStorage` 에 통째로 저장**한다.

```js
localStorage.setItem('user', JSON.stringify(userData));
```

그래서 **프로필 기능이 붙기 전에 로그인해 둔 사용자**는 예전 형태의 객체를 들고 있다.
프로필 필드가 비어 보이면 한 번 로그아웃 후 재로그인하면 채워진다.

## 누적 주행 통계

`controller/RideRecordController.java`

```java
// 프로필에 보여줄 누적 통계 — 기록이 많지 않은 서비스 규모라 그냥 합산한다
@GetMapping("/stats")
public Map<String, Object> stats(@RequestParam Long userId) {
    List<RideRecord> records = rideRecordRepository.findByUserIdOrderByRidedAtDesc(userId);
    double totalDistanceKm = records.stream().mapToDouble(RideRecord::getDistanceKm).sum();
    int totalDurationMin   = records.stream().mapToInt(RideRecord::getDurationMin).sum();
    return Map.of(
            "rideCount", records.size(),
            "totalDistanceKm", totalDistanceKm,
            "totalDurationMin", totalDurationMin
    );
}
```

**기록을 전부 불러와 자바에서 합산한다.** 지금은 기록이 적어 문제없지만,
쌓이면 SQL 집계로 바꿔야 한다.

```sql
-- 나중에 이렇게 바꾸면 됨
SELECT COUNT(*), COALESCE(SUM(distance_km),0), COALESCE(SUM(duration_min),0)
  FROM ride_records WHERE user_id = ?
```

현재 방식은 기록 1000건이면 1000행을 메모리로 가져온다. **집계는 DB 가 하는 편이 훨씬 빠르다.**

## ride_records 에 붙은 코스 정보

```java
// 어떤 코스를 탔는지 — 자유주행이면 둘 다 null.
// routeName은 라이딩 종료 시점의 스냅샷이다(코스가 나중에 지워지거나 바뀌어도
// 이미 탄 기록은 그대로 남아야 하므로).
private Long routeId;
private String routeName;

// routes.ascend_m 을 조인해서 채운다 — ride_records 에 따로 저장하지 않는다(용량 중복 방지).
@Transient
private Integer ascendM;
```

**`routeName` 은 복사하고 `ascendM` 은 조인하는 이유가 다르다.**

| 필드 | 방식 | 근거 |
|---|---|---|
| `routeName` | **복사(스냅샷)** | 코스가 삭제·개명돼도 "내가 탄 코스 이름" 은 그대로여야 함 |
| `ascendM` | **조인(`@Transient`)** | 코스의 고정 속성이라 중복 저장할 이유가 없음 |

`@Transient` 는 **DB 컬럼을 만들지 않는다**는 표시다. 자바 객체에만 존재하고,
조회 시점에 `routes` 를 조인해 채운다.

> 이 필드는 처음에 실제 컬럼이었다가 나중에 `@Transient` 로 바뀌었다.
> 그래서 `DB/migrations/004_drop_ride_records_ascend_m.sql` 로 기존 컬럼을 지운다.

## routes.region — 좌표로 구한 행정구역

```java
// 출발지 좌표 기준 행정구역(구/시) — 카카오 coord2regioncode로 저장 시점에 채운다.
// fromLabel(장소명)은 구 이름이 안 들어있는 경우가 많아 좌표 기반으로 따로 둔다.
@Column(length = 300)
private String region;
```

`fromLabel` 은 "○○공원", "△△역" 처럼 **장소명**이라 지역을 알 수 없다.
지역별 필터를 하려면 좌표 → 행정구역 변환이 필요하다.

`tags` 와 같은 방식으로 **콤마로 이어 붙여** 여러 지역을 담을 수 있다(코스가 구를 넘나들 때).

## ⚠️ 알려진 한계

| 항목 | 내용 |
|---|---|
| 본인 확인 없음 | `PUT /api/users/{id}/profile` 이 **누가 요청했는지 보지 않는다.** id 만 알면 남의 프로필을 고칠 수 있다 |
