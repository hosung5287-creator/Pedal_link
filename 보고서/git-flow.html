main에 아직 안 들어간 브랜치는 sjw(2커밋)와 khs(1커밋)입니다.

05충돌 확인

조합결과근거
khs + sjw 충돌 없음 겹치는 파일 0개 · git merge-tree 정상 종료
로컬 미커밋 변경 + sjw 겹침 4개 constants.js · BrowsePage.jsx · CrewPage.jsx · MapPage.jsx

겹치는 4개 파일은 커밋하거나 stash하지 않으면 sjw 머지가 거부됩니다. 커밋한 뒤 머지하면 같은 줄을 고친 곳에서만 충돌이 납니다.

⚠ VM 배포와 순서가 얽힙니다.
sjw를 머지하면 DB 컬럼이 바뀝니다. VM에 올린 DB와 JAR는 함께 갱신해야 합니다. 한쪽만 바꾸면 백엔드가 뜨지 않을 수 있습니다. 
머지 → 백엔드 실행(update로 컬럼 생성) → 004 마이그레이션 실행
     → 덤프 재생성 → JAR 재빌드 → VM에 둘 다 전송

06머지 순서 (직접 입력)

  1. 미커밋 변경 정리
    sjw와 겹치는 프론트 파일 4개를 커밋하거나 stash합니다. 로그·덤프·.env.production은 커밋하지 않습니다.
  2. main으로 이동 후 sjw 머지
    git switch main
git merge origin/sjw --no-ff -m "Merge branch 'sjw' into main"
  3. khs 머지
    git merge khs --no-ff -m "Merge branch 'khs' into main"
    sjw와 겹치는 파일이 없어서 충돌 없이 끝납니다.
  4. 백엔드 실행해 확인
    ddl-auto=update로 한 번 띄우면 새 컬럼이 만들어집니다. 004 마이그레이션도 실행합니다.
  5. push
    git push origin main
  6. khs를 다시 main 위치로 맞춤 (계속 작업할 경우)
    git switch khs
git merge main
    main이 khs를 포함하므로 새 커밋 없이 앞으로 당겨집니다(fast-forward).
