### ⚠️ JAVA_HOME 문제
시스템 기본 `java` 가 **26**이고 `JAVA_HOME` 이 `C:\Program Files\Java` (디렉터리가 아님)로
잘못 잡혀 있어서 `gradlew` 가 바로 실패한다. 프로젝트는 **JDK 21** 을 쓴다.

```
ERROR: JAVA_HOME is set to an invalid directory: C:\Program Files\Java
```

실행할 때 이렇게 지정하면 된다.
```bash
JAVA_HOME="/c/Program Files/Java/jdk-21.0.12.1" ./gradlew bootRun
```
> 근본 해결: 시스템 환경변수 `JAVA_HOME` 을 `C:\Program Files\Java\jdk-21.0.12.1` 로 수정

| `rider_records` | 0 | ⚠️ **정체불명 — 아래 참고** |

### `routes` 에 이번에 붙은 컬럼
```
distance_km  DOUBLE PRECISION   거리 km
ascend_m     INTEGER            상승고도 m   ← @Column(name="ascend_m") 로 이름 고정
time_min     INTEGER            예상 소요 분
description  VARCHAR(500)       게시물 문구
tags         VARCHAR(300)       해시태그 "야경,초보코스,한강"
```
전부 `ddl-auto=update` 가 자동 생성했다.
**기존에 저장돼 있던 경로 3건은 전부 `NULL`** 이라 피드에서 `-` 로 보인다.

> `ascendM` 을 그냥 두면 컬럼이 `ascendm` 으로 생성된다 (`distance_km` 처럼 밑줄이 안 붙음).
> 잘못 생긴 `ascendm` 컬럼은 `ALTER TABLE routes DROP COLUMN ascendm` 으로 정리했다.

### ⚠️ `rider_records` — 쓰지 않는 테이블
```
id, created_at, end_point, route_distance, start_point, time, user_id  (0행)
```
- 소스 어디에도 `rider_records` 를 참조하는 코드가 **없다**
- 내가 만든 주행 기록 테이블은 `ride_records` (이름이 헷갈리게 비슷하다)
- 예전에 만들었다가 엔티티만 지워진 잔재로 보인다 → **삭제 후보**

### `users` 의 옛 컬럼 잔재
`login_id`, `password_hash` 는 `User` 엔티티에 없어서 아무도 안 쓴다.
`ddl-auto=update` 는 컬럼을 지우지 않으므로 계속 남아 있다.

### ⚠️ DB 덤프가 낡았다
`DB/dump-Pedal_link-202607241122.sql` 은 **7/24 기준**이라
`parties`, `party_members`, `ride_records`, `route_likes` 와 `routes` 의 새 컬럼이 전부 없다.
복원 후 백엔드를 한 번 띄우면 `ddl-auto=update` 가 만들어주긴 하지만, **덤프 갱신 필요.**

## 7. 알려진 문제 (미해결)

1. **파티 개설 직후 응답에 호스트가 안 들어온다**
   `createParty` 가 같은 트랜잭션에서 `findById` 로 다시 읽는데 영속성 컨텍스트에 캐시된
   `members` 가 갱신되지 않아 빈 배열이 온다. DB에는 정상 저장돼 있고 새로고침하면 보인다.
   → `saved.getMembers().add(hostMember)` 를 넣거나 조회를 트랜잭션 밖으로.

2. **`userId` 를 요청 body 로 받아서 사칭이 가능하다**
   게시물 올리기의 403 검사도 남의 `userId` 를 적으면 통과한다. 토큰 인증 필요.

3. **`PartyService` 의 예외가 500 으로 나간다**
   "이미 신청했습니다" 같은 사용자 실수도 `RuntimeException` → 500.
   `@RestControllerAdvice` 로 400 변환 필요.

4. `PartyPage.js:192` eslint 경고 (useEffect 의존성) — 유일하게 남은 컴파일 경고

5. `build.gradle` 에 중복 의존성 몇 줄 (web, data-jpa, lombok, postgresql)

6. `RouteService.java` 가 `service/` 가 아니라 `dto/` 패키지에 있다 (동작은 정상)

7. 피드에 페이징이 없다 — 저장된 경로를 **전부** 한 번에 내려준다
