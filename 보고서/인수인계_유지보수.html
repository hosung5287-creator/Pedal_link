03자주 하는 작업

① 브랜치 머지

이 프로젝트는 항상 --no-ff로 머지해 이력을 남깁니다.

git fetch origin
git log --oneline main..origin/sjw        # 가져올 게 있는지 먼저 확인
git merge origin/sjw --no-ff -m "Merge branch 'sjw' into main"
git push origin main
미커밋 변경이 있으면 머지가 거부됩니다. 먼저 커밋하거나 git stash로 빼두세요. 같은 파일을 양쪽에서 고쳤다면 stash보다 커밋이 안전합니다 — 충돌 시 git merge --abort로 되돌릴 수 있습니다.

② DB 스키마를 바꿀 때

엔티티에 필드를 추가하면 ddl-auto=update가 컬럼을 자동 생성합니다. 다만 조건이 있습니다.

추가하는 타입결과이유
String Integer Long 안전nullable이라 기존 행에 NULL이 들어감
boolean int (원시타입) 실패NOT NULL인데 기본값이 없어 기존 행을 채울 수 없음

원시타입을 넣어야 하면 마이그레이션 SQL을 직접 쓰세요.

-- DB/migrations/00N_설명.sql
ALTER TABLE party_members
    ADD COLUMN IF NOT EXISTS ready BOOLEAN NOT NULL DEFAULT FALSE;

③ 터널로 외부 공개 (휴대폰 시연)

# 터널 2개를 각각 다른 창에서
C:\Users\kimHosung\cloudflared.exe tunnel --url http://localhost:8080   # 백엔드
C:\Users\kimHosung\cloudflared.exe tunnel --url http://localhost:3000   # 프론트

백엔드 터널 주소를 .env.local에 넣고 Vite를 재시작합니다.

VITE_API_BASE=https://받은주소.trycloudflare.com
주소는 터널을 열 때마다 바뀝니다. 미리 링크를 배포하거나 보고서에 적을 수 없습니다. 발표 직전에 열고 끝날 때까지 끄지 마세요.

④ 새 DB 덤프 만들기

cd DB
$env:PGPASSWORD = "pass"
pg_dump -U postgres -d Pedal_link -F p --no-owner --no-privileges -f dump-new.sql

--no-owner --no-privileges는 다른 서버에 복원할 때 소유권 구문이 에러를 내지 않게 합니다.

04실제로 겪은 함정

모두 이번 작업 중 실제로 막혔던 것들입니다. 증상만 보면 원인을 짐작하기 어려운 순서로 정리했습니다.

화면은 뜨는데 로그인·조회가 전부 실패한다

.env.local이 죽은 터널 주소를 가리키고 있거나, 수정 후 Vite를 재시작하지 않은 경우입니다. .env.local은 Vite 시작 시점에만 읽히므로 새로고침으로는 반영되지 않습니다.

VITE_API_BASE=http://localhost:8080   # 로컬 개발이면 이 값
# 저장 후 Vite 종료 → npm run dev 다시

백엔드는 "Started"인데 특정 기능만 깨진다

ddl-auto=update가 컬럼 생성에 실패했는데 WARN만 남기고 정상 기동한 경우입니다. 로그를 끝까지 읽지 않으면 놓칩니다.

Select-String backend.log -Pattern "Error executing DDL"

비로그인 상태에서 버튼을 누르면 화면이 하얘진다

onMoveLogin은 e.preventDefault()를 호출하므로 이벤트 객체를 넘겨야 합니다. ?.는 함수 없음만 막아주지 인자 누락은 막지 못합니다.

onClick={() => onMoveLogin?.()}        // ✗ e가 undefined
onClick={(e) => onMoveLogin(e)}        // ✓

다른 PC에서 접속하면 화면만 뜨고 아무것도 안 된다

localhost는 그 코드를 실행하는 기계 자신을 뜻합니다. 브라우저에서 실행되므로, 다른 PC에서는 그 PC의 8080을 찾다가 실패합니다. CORS 허용 목록에도 그 주소를 추가하고 백엔드를 다시 띄워야 합니다.

휴대폰에서 위치 공유·지오펜싱만 동작하지 않는다

브라우저는 HTTP에서 GPS를 차단합니다. localhost만 예외입니다. 휴대폰 시연에는 터널(HTTPS)이 필수입니다. 이때 프론트만 HTTPS로 열면 혼합 콘텐츠로 API가 막히므로 백엔드 터널도 함께 필요합니다.

경로를 저장했는데 목록에 안 나온다

저장 후 목록 state를 갱신하지 않으면 낡은 값이 남습니다. 현재는 confirmSaveRoute에서 getRoutes를 다시 호출하도록 고쳐져 있습니다. 비슷한 화면을 새로 만들 때 같은 실수를 하기 쉽습니다.

리눅스 서버 작업에서

dnf 명령이 응답 없이 멈춘 것처럼 보인다

| grep으로 넘기면 dnf가 묻는 질문이 grep에 걸러져 화면에 안 보입니다. 답을 기다리며 멈춰 있는 상태입니다.

dnf list available | grep "postgresql18"   # ✗ 질문이 안 보임
dnf list available postgresql18-server     # ✓ dnf 자체 필터

scp가 성공했다는데 서버에 파일이 없다

콜론을 빠뜨리면 로컬 복사가 됩니다. 1 file(s) copied가 떠서 성공처럼 보입니다. 비밀번호를 물어보면 원격 전송, 안 물어보면 로컬 복사입니다.

scp dump.sql user1@192.168.0.5          # ✗ 이 이름의 파일로 복사됨
scp dump.sql user1@192.168.0.5:~/       # ✓

psql: peer 인증을 실패했습니다

PostgreSQL 기본값은 리눅스 계정명과 DB 계정명이 같아야 통과시킵니다. 비밀번호는 보지도 않습니다.

psql -U postgres -d Pedal_link          # ✗ user1이 postgres 행세
sudo -u postgres psql -d Pedal_link     # ✓ 계정 자체를 바꿈

덤프 복원이 type "geometry" does not exist로 실패

CREATE EXTENSION postgis를 해당 DB 안에서 실행하지 않은 경우입니다. \c Pedal_link로 이동한 뒤 실행해야 합니다. DB를 만들었다고 그 안에 있는 게 아닙니다.

버전 규칙 하나만 기억하세요. PostgreSQL 덤프는 낮은 버전 → 높은 버전만 복원됩니다. 현재 18.3이므로 16이 깔린 서버에는 들어가지 않습니다. 서버에도 18 계열을 설치해야 합니다.

알려진 보안 · 설계 이슈

이슈내용
경로 삭제에 소유자 검사 없음 POST /api/routes/delete가 userId를 받지 않아 routeId만 알면 남의 경로를 지울 수 있음
파티 승인에 호스트 검사 없음 approve·reject에 권한 검사가 없음 (매칭 쪽은 SecurityException으로 막혀 있음)
피드가 미공개 경로도 노출 FeedService가 조건 없이 전체를 조회
DB 비밀번호가 pass 로컬은 괜찮지만 서버로 옮길 때 반드시 변경
build.gradle 중복 선언 starter-web·data-jpa·lombok이 두 번씩
가장 큰 구조적 리스크는 스키마 관리 방식입니다. 현재 ddl-auto=update + 손으로 실행하는 SQL 조합이라, 코드와 DB가 어긋나도 즉시 드러나지 않습니다. 서버 운영을 이어갈 계획이면 Flyway 도입과 ddl-auto=validate 전환을 권합니다.
