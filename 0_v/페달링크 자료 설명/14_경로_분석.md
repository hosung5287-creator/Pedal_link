# 경로 분석 — 거리 · 상승고도 · 노면/도로종류 분포

> 경로를 탐색하면 왼쪽 패널 아래에 나오는 **통계 + 가로 막대 그래프**.
> BRouter가 응답에 함께 실어주는 구간 정보를 프론트에서 집계해 만든다. **백엔드는 관여하지 않는다.**

## 1. BRouter 응답에 뭐가 들어있나

`format=geojson` 으로 요청하면 좌표(`geometry.coordinates`) 말고도
`properties` 에 요약값과 **구간별 상세 표(messages)** 가 들어온다.

```json
{
  "type": "Feature",
  "properties": {
    "track-length": "12437",          // 총 거리 (미터, 문자열!)
    "filtered ascend": "86",          // 상승고도 (미터)
    "total-time": "2820",             // 예상 소요 (초)
    "messages": [
      ["Longitude","Latitude","Elevation","Distance","CostPerKm","...","WayTags"],   // ← 헤더 행
      ["12697000","3756000","15","230","...","highway=cycleway surface=asphalt"],
      ["12697500","3756400","16","180","...","highway=residential surface=paving_stones"]
    ]
  },
  "geometry": { "type": "LineString", "coordinates": [[126.97, 37.56], ...] }
}
```

**`messages` 의 첫 번째 행이 헤더**라는 게 핵심이다. 컬럼 순서가 고정이 아닐 수 있으므로
인덱스를 하드코딩하지 않고 헤더에서 찾는다.

## 2. 파싱 코드 읽기 (parseBrouterStats)

```js
function parseBrouterStats(props) {
  // ① 요약값 — 전부 문자열로 오므로 Number() 변환. 없으면 0
  const distanceM = Number(props['track-length']) || 0;
  const ascendM   = Number(props['filtered ascend']) || 0;
  const timeSec   = Number(props['total-time']) || 0;

  // ② 헤더 행에서 필요한 컬럼의 위치를 찾는다
  const messages = props.messages || [];
  const header = messages[0] || [];
  const dIdx = header.indexOf('Distance');   // 이 구간의 길이
  const wIdx = header.indexOf('WayTags');    // 이 구간의 도로 태그

  // ③ 구간을 돌면서 노면별 / 도로종류별 미터를 누적
  const surfaceM = {};
  const highwayM = {};
  if (dIdx >= 0 && wIdx >= 0) {
    for (let i = 1; i < messages.length; i++) {     // i=1 부터 (0은 헤더)
      const seg  = Number(messages[i][dIdx]) || 0;
      const tags = messages[i][wIdx] || '';         // "highway=cycleway surface=asphalt"

      let surface = 'unknown';
      let highway = 'unknown';
      tags.split(/\s+/).forEach((t) => {            // 공백으로 쪼개고
        const [k, v] = t.split('=');                // key=value 로 다시 쪼갬
        if (k === 'surface') surface = v;
        else if (k === 'highway') highway = v;
      });

      surfaceM[surface] = (surfaceM[surface] || 0) + seg;   // 누적
      highwayM[highway] = (highwayM[highway] || 0) + seg;
    }
  }

  // ④ 객체 → 정렬된 배열 + 퍼센트
  const toSorted = (obj) => {
    const total = Object.values(obj).reduce((a, b) => a + b, 0) || 1;   // 0 나눗셈 방지
    return Object.entries(obj)
      .map(([key, meters]) => ({ key, meters, pct: Math.round((meters / total) * 100) }))
      .sort((a, b) => b.meters - a.meters);          // 긴 것부터
  };

  return {
    distanceKm: Math.round(distanceM / 100) / 10,    // 12437m → 12.4km
    ascendM,
    timeMin: Math.round(timeSec / 60),
    surfaces: toSorted(surfaceM),
    highways: toSorted(highwayM),
  };
}
```

### 짚어볼 기법 4가지

**① `Number(x) || 0`** — 값이 없거나 숫자가 아니면 `NaN` 이 되는데, `NaN` 은 falsy 이므로 `0` 이 된다.

**② `Math.round(m / 100) / 10`** — 소수점 1자리 반올림 관용구.
`12437 / 100 = 124.37` → 반올림 `124` → `/10 = 12.4`.

**③ 객체를 카운터로 쓰기** — `obj[key] = (obj[key] || 0) + 값`.
처음 보는 키면 `undefined || 0` 으로 0부터 시작한다. 집계할 때 매우 자주 쓰는 패턴.

**④ `|| 1` 로 0 나눗셈 방지** — 구간이 하나도 없으면 total이 0이 되어 `0/0 = NaN` 이 나온다.

## 3. 반환 형태와 사용

```js
// requestBrouterRoute 의 반환값
return {
  coords: coordinates.map(([lng, lat]) => [lat, lng]),   // Leaflet용 좌표
  stats: parseBrouterStats(feature?.properties || {}),   // 분석 결과
};
```

```js
// MapPage.js — findRoutes
const [bike, short] = await Promise.all([
  requestBrouterRoute(from, to, 'trekking'),
  requestBrouterRoute(from, to, 'shortest'),
]);
setRouteStats(bike.stats);     // ★ 자전거 경로(trekking)의 통계만 표시한다
```

경로를 초기화하면 통계도 같이 지운다.
```js
const resetPlanner = useCallback(() => {
  ...
  setRouteStats(null);
}, []);
```

## 4. 렌더링 — AnalysisBar 컴포넌트

```jsx
const ANALYSIS_PALETTE = ['#0ea5e9', '#22c55e', '#f59e0b', '#a855f7', '#ef4444', '#14b8a6', '#64748b', '#eab308'];

function AnalysisBar({ title, items, labels }) {
  const top = items.slice(0, 6);                 // 상위 6개만 (나머지는 너무 잘아서 생략)
  return (
    <div className="analysisGroup">
      <h4 className="analysisTitle">{title}</h4>

      {/* 가로 막대 — 퍼센트를 width 로 준다 */}
      <div className="analysisTrack">
        {top.map((it, i) => (
          <span key={it.key} className="analysisSeg"
            style={{ width: `${it.pct}%`,
                     background: ANALYSIS_PALETTE[i % ANALYSIS_PALETTE.length] }}
            title={`${labels[it.key] || it.key} ${it.pct}%`} />
        ))}
      </div>

      {/* 범례 */}
      <ul className="analysisLegend">
        {top.map((it, i) => (
          <li key={it.key}>
            <span className="legendDot" style={{ background: ANALYSIS_PALETTE[i % ANALYSIS_PALETTE.length] }} />
            <span className="legendName">{labels[it.key] || it.key}</span>
            <span className="legendPct">{it.pct}%</span>
          </li>
        ))}
      </ul>
    </div>
  );
}
```

**`i % PALETTE.length`** — 항목이 팔레트 색보다 많아져도 색이 처음부터 순환한다.

**`labels[it.key] || it.key`** — 한글 라벨이 없는 태그는 영어 원문을 그대로 보여준다.
이렇게 해두면 모르는 태그가 와도 화면이 비어 보이지 않는다.

사용:
```jsx
{routeStats && (
  <>
    <div>거리 {routeStats.distanceKm} · 상승 {routeStats.ascendM} · 시간 {routeStats.timeMin}</div>
    <AnalysisBar title="노면"      items={routeStats.surfaces} labels={SURFACE_LABELS} />
    <AnalysisBar title="도로 종류" items={routeStats.highways} labels={HIGHWAY_LABELS} />
  </>
)}
```

```js
const HIGHWAY_LABELS = {
  cycleway: '자전거도로', path: '소로', footway: '보행로', pedestrian: '보행자도로',
  residential: '주택가길', living_street: '생활도로', service: '이면도로', track: '농로',

```

이 키들은 **OpenStreetMap의 표준 태그값**이다. 새 값이 보이면 여기에 추가하면 된다.
- surface 값 목록: https://wiki.openstreetmap.org/wiki/Key:surface
- highway 값 목록: https://wiki.openstreetmap.org/wiki/Key:highway

> `steps`(계단)가 경로에 섞여 나오면 자전거로 갈 수 없는 구간이라는 뜻 —
> "이 경로에 계단이 N% 포함" 같은 경고를 띄우면 유용하다.

## 6. 이 기능과 헷갈리기 쉬운 것 — routeHasCycleways()

비슷한 이름이지만 **완전히 다른 기능**이다.

| | `parseBrouterStats` | `routeHasCycleways` |
|---|---|---|
| 데이터 출처 | BRouter 응답의 태그 | **우리 DB의 `cycleways` 테이블** |
| 하는 일 | 노면/도로종류 비율 계산 | 경로가 서울시 자전거도로와 겹치는지 여부(true/false) |
| 결과 | 막대 그래프 | 상태 메시지 "경로 2개를 표시했습니다" / "해당 경로에 자전거 도로가 없습니다" |

```js
// routeHasCycleways — 점과 선분 사이 거리로 근접 판정 (약 20m 이내면 겹친 것으로 봄)
const THRESHOLD = 0.0002;                                  // 도(degree) 단위 ≈ 20m
const step = Math.max(1, Math.floor(routePoints.length / 80));   // 최대 80개 점만 검사 (속도)
```
경로의 모든 점을 다 검사하면 느리므로 **80개만 샘플링**한다. 정확도를 조금 포기하고 속도를 얻은 것.

## 7. 개선 후보

| 난이도 | 과제 |
|--------|------|
| ★ | 최단 경로(`short.stats`)의 통계도 함께 보여주고 두 경로 비교 |
| ★ | 계단·비포장 비율이 높으면 경고 문구 표시 |
| ★★ | ~~거리를 경로 저장 시 함께 DB에 저장~~ → ✅ 완료: `routes.distance_km` 에 저장되어 파티 카드에서도 쓰인다. 상승고도·소요시간도 같은 방식으로 추가할 수 있다 |
| ★★ | 고도 프로파일 그래프 (messages의 `Elevation` 컬럼 활용) |
