# 개발계획서 표준 작성 가이드

> 졸업작품 개발계획서를 **누가 써도 같은 구조·형식**으로 작성하기 위한 표준 문서입니다.
> 2019 / 2020 / 2023년 샘플 3건을 분석해 공통 골격을 뽑고, 서로 달랐던 부분을 하나로 통일했습니다.
>
> 이 문서는 두 부분으로 구성됩니다.
> - **A. 작성 지침** — 섹션별로 무엇을, 어떻게, 얼마나 쓰는지에 대한 설명과 예시
> - **B. 복사용 빈 템플릿** — 그대로 복사해 내용만 채우면 되는 골격 (맨 아래 [8번](#8-복사용-빈-템플릿))

## 1. 공통 원칙 (먼저 읽기)

| 항목 | 표준 |
|---|---|
| **문서 종류** | 졸업작품 개발계획서 |
| **분량** | A4 2~3쪽 (표지 제외) |
| **용지·여백** | A4 세로, 상하 여백 약 1.9cm / 좌우 약 2.5cm (샘플 공통값 유지) |
| **섹션 구성** | 아래 6개 섹션 **순서·제목 고정** (2번 참고) |
| **제목(헤딩) 표기** | `한글 (English)` 이중 언어 병기 — 예: `배경 (Background)` |
| **본문 글꼴** | 맑은 고딕 11pt (제목은 Heading 1 스타일) |
| **글머리 기호** | 목록은 **불릿(`•`) 사용**, 하위 항목은 들여쓰기된 대시(`-`). 수동 하이픈+공백 나열 금지 |
| **번호 목록** | "기대효과"처럼 개수를 강조할 때만 `1. 2. 3.` 사용 |
| **문체** | 개조식(명사형 종결) 원칙. 예: "~ 제공한다" 대신 "~ 제공" / "~를 개발" |
| **용어 통일** | 한 문서 안에서 같은 대상은 같은 단어로. 오탈자·띄어쓰기 최종 점검 필수 |

**핵심 규칙 3가지**
1. **6개 섹션의 순서와 제목은 바꾸지 않는다.** (내용이 없으면 "해당 없음"이라 쓰되 섹션은 유지)
2. **모든 목록은 같은 방식(불릿)으로 쓴다.** 파일마다 하이픈·불릿을 섞지 않는다.
3. **작업계획일정표의 열 구성과 간트 막대 규칙([5번](#5-작업계획일정표-상세-규칙))을 지킨다.**

## 4. 섹션별 작성 지침

각 섹션은 **[목적] → [작성 방법] → [예시] → [체크]** 순서로 설명합니다.
예시는 샘플에서 뽑아 표준 형식에 맞게 다듬은 것입니다.

### 4.1 배경 (Background)
- **목적:** 이 주제를 왜 선정했는지(문제의식·동기·시장 흐름)를 설명.
- **작성 방법:** 2~3문장의 문단, 또는 불릿 2~3개. "무엇이 불편/필요했다 → 그래서 이걸 만든다" 흐름.
- **예시:**
  > • 학과 커리큘럼이 웹·앱 개발 중심이라 이를 응용할 수 있는 주제로 선정
  > • 게임 플랫폼마다 할인율이 달라 같은 게임도 가격이 제각각 → 최저가 비교 서비스 필요
- **체크:** ☐ "왜 만드는가"에 대한 답이 되는가 ☐ 3문장 이내로 간결한가

### 4.2 목적/목표 (Objectives)
- **목적:** 프로젝트가 달성하려는 결과를 명확히.
- **작성 방법:** 불릿 2~4개. 각 항목은 "무엇을 → 어떻게 → 무슨 효과" 한 줄.
- **예시:**
  > • 여러 게임 사이트의 가격을 모아 최신 가격으로 비교·구매하도록 지원
  > • 협동 플레이로 팀이 난관을 헤쳐나가는 흥미 유발
- **체크:** ☐ 배경에서 제기한 문제와 연결되는가 ☐ 측정·확인 가능한 표현인가

### 4.3 범위 (Scope)
- **목적:** 만들 기능의 경계를 정함 (포함/제외).
- **작성 방법(통일):** **기능 모듈(대분류)** 을 굵게 쓰고, 그 아래 **세부 기능을 대시(-)로** 들여쓰기.
  - 대분류는 명사(예: 회원관리, 채팅, 게시판, 게임, 뉴스, 프로필 …)
  - 세부 기능은 "~할 수 있다" 또는 개조식 한 줄
- **예시:**
  > **회원관리**
  > - 회원가입 시 이메일 인증으로 보안 강화
  > - 로그인 / 로그아웃
  >
  > **게임 가격 비교**
  > - 스팀·에픽·PS·닌텐도에서 크롤링한 정보를 PC/콘솔로 분류해 가격 표시
- **체크:** ☐ 모든 항목이 "대분류 → 세부" 2단 구조인가 ☐ 접근방법·일정과 기능명이 일치하는가

### 4.4 접근방법 (Approach)
- **목적:** 어떤 기술·방법으로 구현하는지.
- **작성 방법(통일):** 아래 **3개 라벨 고정**. 각 라벨 뒤에 콜론(:)으로 나열. (필요 시 `역할분담` 추가)
  - **개발환경:** 언어 / 프레임워크 / DB / 서버 등
  - **주요활동:** 핵심 개발 활동 나열
  - **산출물:** 최종 결과물 형태 (웹 페이지 / 윈도우 프로그램 / 서버 등)
- **예시:**
  > - **개발환경:** Spring, Python, MySQL, AWS
  > - **주요활동:** 플랫폼 크롤링, 가격 비교, 추천 시스템, 게시판
  > - **산출물:** 반응형 웹 페이지, 크롤링 서버
  > - **역할분담(선택):** 홍길동-백엔드, 김철수-크롤러, 이영희-프론트
- **체크:** ☐ 3개 라벨을 모두 채웠는가 ☐ 범위의 기능을 구현할 기술이 빠짐없이 있는가

### 4.5 작업계획일정 (Workplan)
- **목적:** 기간별로 무엇을 언제 하는지 간트 표로 표현.
- **작성 방법:** [5번 상세 규칙](#5-작업계획일정표-상세-규칙)을 그대로 따름.
- **체크:** ☐ 표 열 구성이 표준과 같은가 ☐ 간트 막대 색상·범례 규칙을 지켰는가 ☐ 주차가 1주부터 시작하는가

### 4.6 비용 / 기대효과 분석 (Cost-Benefit Analysis)
- **목적:** 이 결과물이 주는 이점·효과(사용자·기술·팀 관점).
- **작성 방법(통일):** **번호 목록 `1. 2. 3.`** 3~6개. 각 항목 한 줄, 개조식.
- **예시:**
  > 1. 여러 사이트를 돌지 않고 한 곳에서 최저가 비교 가능
  > 2. 추천 시스템으로 선호 장르 게임을 추천받음
  > 3. 뉴스 기능으로 최신 업데이트 정보 확인
- **체크:** ☐ 목적/목표와 대응되는가 ☐ 과장·비속어 없이 객관적 표현인가

## 5. 작업계획일정표 상세 규칙

세 샘플이 가장 많이 달랐던 부분입니다. 아래 규칙으로 통일합니다.

### 5.1 열(칼럼) 구성 — 표준
왼쪽 2개 고정 열 + 주차 열.

| 구분 | 세부 항목 | 1주 | 2주 | 3주 | 4주 | 5주 | 6주 | 7주 | 8주 | … |
|---|---|---|---|---|---|---|---|---|---|---|
| (작업 영역) | (세부 작업명) | | | | | | | | | |

- **1열 `구분`**: 작업 영역/단계 (예: 기획, 서버, 프론트, 공통, 테스트). 같은 구분이 여러 행이면 셀 병합.
- **2열 `세부 항목`**: 구체 작업명. (기존 `세부 항목명`·`구현내용` 명칭을 `세부 항목`으로 통일)
- **주차 열**: **반드시 `1주`부터** 시작. (샘플 2020은 `2주`부터 시작해 1주가 누락됨 → 금지)
- 주차 수는 프로젝트 기간에 맞춰 조정(예: 10~15주). 라벨은 `N주` 형식으로 통일.

### 5.2 간트 막대 표현 규칙 (셀 음영)
작업이 진행되는 주차 칸에 **셀 배경색(음영)** 을 칠해 막대로 표현합니다.

- **색상은 `구분(작업 영역)`별로 하나씩 배정**하고, 그 구분의 모든 행은 같은 색을 사용. (2020 방식 채택 — 가장 가독성 높음)
- 검정·짙은 회색 단색으로만 칠하던 방식(2019·2023)은 지양. 구분을 색으로 나눠 한눈에 보이게 함.
- 문서 상단 또는 하단에 **범례**를 넣어 색-구분 매칭을 표시.
- 권장 팔레트 (원하면 교체 가능):

  | 구분(예시) | 색상 이름 | HEX |
  |---|---|---|
  | 기획 | 파랑 | `#4472C4` |
  | 서버/백엔드 | 주황 | `#ED7D31` |
  | 프론트/클라이언트 | 초록 | `#70AD47` |
  | 공통/디자인 | 보라 | `#7030A0` |
  | 테스트/마무리 | 회색 | `#808080` |

### 5.3 Markdown에서의 표기(이 가이드·초안용)
Word로 옮기기 전 초안에서는 채워진 칸을 `█`(또는 `■`)로 표시하면 그대로 셀 음영으로 옮기기 쉽습니다.

```
| 구분 | 세부 항목 | 1주 | 2주 | 3주 | 4주 | 5주 | 6주 | 7주 | 8주 |
|------|-----------|----|----|----|----|----|----|----|----|
| 기획 | 주제 선정·역할 분배 | █ | █ |   |   |   |   |   |   |
| 기획 | 기능 회의·화면 설계 |   | █ | █ |   |   |   |   |   |
| 서버 | DB 구축         |   |   | █ | █ | █ |   |   |   |
| 서버 | 크롤링 프로그램  |   |   |   | █ | █ | █ |   |   |
| 프론트 | 메인·로그인 페이지 |   |   |   |   | █ | █ | █ |   |
| 공통 | 테스트·학술제 준비 |   |   |   |   |   |   | █ | █ |
```

### 5.4 Word에서 만드는 법 (요약)
1. `표 삽입`으로 (행=작업 수+헤더, 열=2+주차 수) 표 생성
2. 첫 행에 `구분 / 세부 항목 / 1주 / 2주 …` 입력
3. 각 작업이 진행되는 칸 선택 → `표 디자인 ▸ 음영`에서 구분별 색 적용
4. 같은 `구분` 행들은 1열 셀을 병합
5. 표 아래 범례(색-구분) 추가

## 6. 서식·스타일 규칙 요약

| 요소 | 표준 규칙 |
|---|---|
| 섹션 제목 | Heading 1, `한글 (English)` 병기 |
| 본문 | 맑은 고딕 11pt, 개조식 |
| 1단계 목록 | 불릿 `•` |
| 2단계 목록 | 들여쓴 대시 `-` |
| 번호 목록 | 기대효과 등 개수 강조 시 `1. 2. 3.` |
| 라벨식 항목 | `라벨:` 뒤 한 칸 띄고 내용 (예: `개발환경: …`) |
| 표 | 머리행 음영, 가운데 정렬, 표 아래 범례 |
| 페이지 번호 | 하단 가운데 |
| 색상 | 간트 막대는 6.2절 팔레트 사용, 본문 색은 검정 |
| 금지 | 하이픈·불릿 혼용, 섹션 순서 변경, 주차 2주부터 시작, 빈 라벨 방치 |

## 7. 제출 전 체크리스트

- ☐ 표지 블록(프로젝트명·조·팀원·작성일)이 있는가
- ☐ 6개 섹션이 표준 순서·제목으로 모두 있는가
- ☐ 제목이 `한글 (English)` 병기인가
- ☐ 모든 목록이 불릿 방식으로 통일됐는가 (하이픈 수동 나열 없음)
- ☐ 범위가 "대분류 → 세부" 2단 구조인가
- ☐ 접근방법에 `개발환경/주요활동/산출물` 3라벨이 모두 있는가
- ☐ 일정표 열이 `구분 / 세부 항목 / N주`이고 1주부터 시작하는가
- ☐ 간트 막대가 구분별 색상 + 범례로 표현됐는가
- ☐ 기대효과가 번호 목록 3개 이상인가
- ☐ 파일명이 `YYYY-학기-조_개발계획서.docx` 규칙을 따르는가
- ☐ 오탈자·띄어쓰기·용어 통일 최종 점검했는가
